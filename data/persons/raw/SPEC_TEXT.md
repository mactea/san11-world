# 从史书原文抽取人物（子代理用）

目的：给三国志11 扩展武将名单（公元 170–370 年）从史书原文里列出**原文中出现、有具体事迹的人物**。
只依据你读到的这段原文，不要凭记忆补原文里没有的事（年份、官职、亲属、事迹都要原文里有）。
原文是简体，输出也用简体（繁体转换由后续脚本做）。

## 收谁
* 收：在本段时间范围内活动的具体个人——君主、宗室、后妃、将领、官员、谋士、宦官、外戚、名士、隐士、方士、僧道、
  起义/叛军首领、外族（匈奴、鲜卑、乌桓、羌、氐、羯、蛮、夷、高句丽、夫余、倭等）首领和将领。
* 不收：本段之前的古人（只是被引用的周公、汉高祖、霍光等）；只有职务没有名字的人（「某太守」）；
  群体（「黄巾」「诸羌」）；神话人物。
* 只出现一次但有具体动作（被任命、出征、被杀、上书、投降……）的人也收。
* 只知姓的后妃、女性写作「某氏」（王氏、杨氏）；原文只写名的宗室（「立皇子柬」）可以按上下文补姓，原文写法记进 alias。
  原文只写称号的君主（「帝」「晋王」）按本段可确定的姓名写。
* 同一个人在本段里可能先写全名、后来只写名（「皇甫嵩……嵩」）或只写字、官职、封号：合并成一条。
  同名不同人要分开（用籍贯、官职区分）。

## 输出
写到指定的 JSONL 文件（UTF-8，一行一个 JSON 对象，不要 Markdown 代码块），字段：

```

 "alias": ["左中郎将"],        // 原文里用来指他的其他称呼、封号、小名（可空）
 "sex": "m",                  // m / f
 "origin": "安定朝那",         // 籍贯（原文有才写，否则 ""）

 "polity": "东汉",            // 所属政权或势力，按本段原文时的归属：东汉、董卓、袁绍、曹操、曹魏、蜀汉、孙吴、西晋、东晋、
                             //  前赵（汉赵）、后赵、成汉、前凉、前燕、前秦、代、冉魏、段部、宇文部、慕容部、拓跋部、

                             //  外族首领 / 叛军首领 / 其他
 "offices": ["北地太守", "左中郎将", "车骑将军"],   // 原文出现的官职、爵位，按先后
 "years": [184, 189],         // 本段原文里他活动的第一年和最后一年（公元）
 "birth": null,               // 原文明确给出（或可由「时年 N」推出）才写，否则 null
 "death": null,               // 原文写他死/被杀/自杀的那一年，否则 null
 "death_violent": false,      // 被杀、战死、自杀、被处死为 true
 "kin": [{"rel": "叔父", "name": "皇甫规"}],     // 原文写到的亲属：父、母、子、女、兄、弟、姊、妹、妻、夫、从兄、从弟、叔父、侄、孙……
```

## 五维估计（三国志11 尺度）
参照光荣设定：吕布武力 100、关羽 97、张飞 98；诸葛亮智力 100、统率 92；曹操统率 96 智力 91 政治 94 魅力 96；
刘备魅力 99；普通文官 30~60、普通武将统率武力 50~70。
* 史书只记一笔的小官：五维 30~60 之间，按职位文武给偏重（太守、尚书偏政治，校尉、都尉偏统率武力）。
* 有战功、多次领兵：统率 65~85；以勇力著称（斩将、先登、陷阵）：武力 75~90。
* 谋略见于记载（献计被采纳、识破计谋）：智力 70~90；治理有政绩、制度建设：政治 70~90；
  得众心、名望高、被众人推戴：魅力 70~90。
* 90 以上只给史书公认的一流人物，并且本段原文有足够的事迹支持。
* 后妃、宦官、名士等不领兵的人统率武力给低（10~40）。

## 纪传体史书（晋书、后汉书、十六国春秋、华阳国志）
* 这些书按人物立传，没有年份标题。只收活动时间与 **公元 170–370 年** 有交集的人：传主、附传、
  传文里有具体事迹的人。东汉中期以前（170 年前已死）和 370 年以后才出仕活动的人不收。
* years 用原文年号推算公元年（如「太康元年」= 280、「永和五年」= 349、「建安十三年」= 208），推不出写 null；
  原文写「年 N 卒」等可推生年的就写 birth。
* src 写「书名·卷名 传名」，如「晋书·卷三十四 羊祜传」「后汉书·卷七十一 皇甫嵩传」「十六国春秋·前燕录三」。
* 传主的 deeds 可以写到 150 字，概括一生主要事迹；附传和传文中的人照常 40~150 字。

## 注意
* 一个块读完再写，别漏掉只出现一两次的人；本段每个具体人物都要有一条。
* 写完自己检查：每行都是合法 JSON；同一人没有重复；没有收本段之前的古人。
* 最后在回复里只报：写了多少人、文件路径、遇到的难点（例如拿不准是否同一人的名字）。
