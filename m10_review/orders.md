# 存档头 +0x184：执行命令中的武将链表（M10 §4.7）

结论：**读完存档后由 DLL 补齐链表（方案 a）**，存档格式不变（仍写 1000 项）。补丁行在
`tools/patchgen/m10_orders.py`（1 个洞，0x493be5），DLL 函数 `personsRebuildOrders` 的规格见 §5。

## 1. 对象和链表

* 世界对象 0x7201958 的基类部分（ctor 0x4830b0，vtable 0x79c134；世界没有覆盖这个 vtable）。
  vtable+0x20 = 0x482cb0（重置，读档前调用，0x482d4e 清空链表 RemoveAll 0x47be50），
  vtable+0x30 = **0x483120**（头序列化）。世界序列化 0x4937b0 第一步就是 `call [vtbl+0x30]`（0x4937e0）——
  **头比武将记录（0x493814 循环）先读**。
* +0x184 = 0x7201adc，通用对象指针链表（CList vtbl 0x79bf44）：+4 表头、+8 表尾、+0xc 个数；
  节点 +0 next、+4 prev、+8 数据（武将指针）。节点池 0x6ee7950（M10 已换成 PPOOL）。

## 2. 谁加、谁删

* **加**：只有 0x482f80（thiscall world, officer；`0x47a630` 有效 + `0x482af0` 不在表里 → AddTail `0x47c1b0`）。
  5 个调用点全部紧跟在 `0x489bd0`（设命令：+0x13c = 种类，+0x140..+0x150 = 参数）之后，种类 0..43：
  0x4a7403 / 0x4a746b（下达命令，种类为参数）、0x4a83dd / 0x4a8655 / 0x4a8a8c（种类 0x25）。
  读档 0x4833b1 直接 AddTail（不查重、不看命令）。
* **删**：只有清理 0x483440：删掉「不是有效对象」或「+0x13c 不在 0..43」的项（0x482fc0）。调用：0x4a1880 和
  0x4a1a20 处理完链表后（0x4a199f、0x4a1bc6），以及回合处理 0x59a081。另有重置 0x482cb0、析构 0x482c50 的 RemoveAll。
  其它 `0x482fc0`/`0x482af0` 调用都作用于别的链表（静态扫描 ecx 来源，没有 0x7201adc / +0x184）。
* 把命令清成 −1（0x4a5780、0x4a8677、0x4a97e6、0x4acb8d）**不**从链表删除；这些项留到下一次清理。
  0x4a1880（据点事件，参数是据点）对其中 −1 的项做「回到所属据点」处理（0x4a0cb0、0x4a5780、0x4a5660），然后清理。
* 官员 +0x13c 只在存档流里存（0x48baaa，在 `0x43a8f0(stream)` 分支内），剧本里没有；武将 ctor 0x488648 置 −1。

**成员条件**：清理之后，链表 = {有效（`0x47a630` ≠ 0，即 vtable+8 = 0x488430：存在且 +0x17c≠0 或 +0xa0∉{6,8}）
且 +0x13c ∈ 0..43 的武将}。两次清理之间还会多出「刚被清成 −1 或已失效」的旧项。

## 3. 顺序是否重要

链表按加入顺序处理：0x4a1880 / 0x4a1a20 的到达处理、0x482f20（找第一个有命令且 0x489120 为 0 的武将）、
0x49f430 / 0x49f4e0 等按势力 / 命令查找。顺序只决定同一天内谁先被处理、查找时先找到谁，不影响正确性。
被截掉的尾巴原本的加入顺序无从恢复（文件里没有），补齐按编号顺序追加在后面。

## 4. 会不会超过 1000

原版：特殊武将（1000..1099）不接命令，能接命令的 ≤ 1000，容量正好够。
扩展后能接命令的是 PS+150 人，链表里 = 移动中 / 执行中的武将 + 待清理旧项。AI 大规模调动时，几千名武将里
同时有 1000 人以上在路上是现实的（P = 5000 时约要 20% 在途，P = 15000 时不到 7%），实际人数要实测（§4.8），
但修法不依赖这个数。

## 5. 修法（方案 a，推荐）

### 补丁（m10_orders.py）
0x4937b0 读档路径（`[ebp+8] == 1`，流类型不是 4 / 0x18）在 0x493be5 `call 0x493400`（各对象读后处理）之后：

```
mov eax, 0x493400; call eax                       ; 原指令
mov ecx, ebp; mov eax, 0x43a8f0; call eax         ; 存档流？（类型 6/0xc/0x11/0x1a/0x1b，与 0x48319f 同一判断）
test eax, eax; je skip
push 0x7201adc; mov eax, {PORDERS}; call eax; add esp, 4
skip:
```
此时武将记录都已读入；eax/ecx/edx 可用（0x493bea 重新装 ecx），ebx/ebp/esi/edi 由被调方保存。
已用 keystone 和 detour.Builder 试编（35 字节）。没有替换任何审查行，SKIP 为空；0x483398 的 P−1 保留，
0x48335f / 0x48336b / 0x4833b7 的 1000 不改（文件仍写 1000 项）。

### DLL 函数
```
extern "C" void __cdecl personsRebuildOrders(void* list);   // list = 0x7201adc；符号名 PORDERS
```
算法：
1. `g_p` 为空就返回。
2. 走一遍链表（不调 exe）：`for (node = *(uint8_t**)(list+4); node; node = *(uint8_t**)node)`，
   `p = *(uint8_t**)(node+8)`；若 `PERSONARR <= p < PERSONARR+PT*0x190` 且 `(p-PERSONARR) % 0x190 == 0`，
   标记 `present[(p-PERSONARR)/0x190] = 1`（`std::vector<uint8_t>(PT)`）。不要用 0x482af0 查重：
   它每个节点调两次 IsBadReadPtr/IsBadWritePtr，PT 次查找是 O(PT²) 的系统调用，太慢。
3. `for id in 0..PT-1`：`p = PERSONARR + id*0x190`；`t = *(int*)(p+0x13c)`；
   `t < 0 || t > 43` → 跳过；`present[id]` → 跳过；`isValid(p) == 0` → 跳过；否则 `addTail(list, p)`，计数。
4. 计数 > 0 时写日志（补了几人、链表现有 `*(int*)(list+0xc)` 项）。

exe 函数（32 位 MSVC 函数指针）：
```
typedef int   (__cdecl*    IsValidFn)(void* obj);              // 0x47a630：IsBadRead/WritePtr + vtable+8；调用方清栈
typedef void* (__thiscall* AddTailFn)(void* list, void* data); // 0x47c1b0：ret 4，自己进出临界区 0x6ee7868，返回节点
```
先查 +0x13c 再调 0x47a630（只对有命令的武将付出 IsBadPtr 的代价）。

### 残余差异（相对「不截断」的原版行为）
* 截掉的尾巴里「已清成 −1 / 已失效」的旧项补不回来。它们本来就会在下一次清理（最迟本回合 0x59a081）时被删；
  唯一的区别是：如果下一次清理前先发生据点事件 0x4a1880，这些武将不会得到「回到所属据点」处理。
  只在链表超过 1000 时才可能发生。
* 补回的项排在文件里 1000 项之后，按编号顺序。

### 旧布局存档
如果读旧存档（1100 人布局）时把 850..1099 搬到 PS..PT−1，文件里的链表编号也要同样换算（在 0x48339f 的
`push eax` 处，与武将记录同一规则）。否则那些项指向别的（空的）武将：它们无效或命令为 −1，会在下一次清理时删掉，
而真正的武将由本函数补齐——不换算也不会出错，只是同一个时机会有一次多余的 −1 处理（同上一条）。

## 6. 方案 b（加大栈数组、改存档格式）为什么不选
* 0x483120 的帧 0xfa4 → 0xfa4 + (L−1000)×4（PT = 15250 时约 60 KB），超过一页要改成 `__chkstk 0x707d40`
  探测（6 字节 `sub esp` 换 10 字节，要洞），0x483129 `0xfb4`、0x483437 `add esp, 0xfa4` 等 esp 偏移跟着改，三个 1000 换成 L。
* 文件格式变：头 2212 字节里这 2000 字节变成 2×L，旧存档仍是 1000 项，读档要按流的标记决定项数（存档目前没有
  像 USTREAM 那样的项数标记），转换工具也要改。
* 好处只有：保留截断尾巴的顺序和待清理旧项——就是 §5 的两条残余差异，都不影响正确性。
* 方案 a：1 个 5 字节洞 + 30 行 C++，存档格式和旧档兼容不变，链表 ≤ 1000 时与原版完全一致。
