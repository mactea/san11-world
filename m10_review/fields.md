# M10 审查：武将表之外存放武将编号的地方

静态分析（pk.asm），没有运行游戏。问题：除武将表本身外，哪些对象/数组存武将编号，内存里和文件里各多宽；
有没有 8 位的武将编号；有没有按武将编号开的数组。

文件写法（helper）：`0x48a970` = u8（`movsx byte` 读回，有符号 −128..127）；`0x48a9e0` = i16（`movsx word`，−32768..32767）；
`0x43b060` = i32；`0x479620` / `0x47ae00` / `0x481c60` 等 = 原样 1/2/4 字节；`0x481ae0/0x481b50/0x481bc0/0x481cc0/0x47fe80/0x47fef0/0x47ff60/0x47ffd0` = 原样字节/dword 数组。
判断字段是武将编号的证据：setter 里 `cmp eax,0x44b`（下面"setter"列）、读出后传给 getter 0x490b00 / 检查 0x412390。
另做了两次全程序扫描（脚本在 scratchpad m10：`pidload.py`、`setter` 扫描、`idx2.py`、`absrange.py`）：
所有"字段 → 0x490b00 / 0x412390 / cmp 0x44b"的加载，以及所有 `cmp eax,0x44b` 型 setter 存到的字段。

结论：
* **没有任何武将编号以 8 位存放**（内存或文件）。全部 u8 字段都核对过不是武将（城市、州、类型 29 等）。
* 文件里所有武将编号都是 i16（有符号，−1 = 无）：P ≤ 32767 不用改格式；P > 32767 要改上表全部 i16 字段、武将记录内的 i16 字段
  （0x48a9e0 / 0x48b650）和头里的 1000 项列表。
* 内存里有两处 **16 位** 武将编号：部队 +0x30（目标，word）和 AI 据点记录 +0x02（word）。P ≤ 32767 没问题；超过则要改结构。
* 其余都是 32 位 int。
* 对象内部没有按武将编号开的数组（类型 18、AI 子对象都没有；它们的数组按势力/城市/据点/部队/旗标号）。

## 2. 存档头 +0x184 的 1000 项列表

**是什么**：头对象 +0x184 是一个链表（vtable 0x79bf44，与部队等用的同一种列表类），节点存**武将指针**。
内容是"身上有任务（指令）的武将"：武将记录 +0x13C 是任务种类（0..43，−1 = 无），+0x140..+0x150 是任务参数，
由 0x489bd0 设置。

* 加入：0x482f80（不重复才 push，0x482af0 查重），调用者 0x4a7403、0x4a746b（下达指令，任务号 0..43）、0x4a83dd（任务 0x25）、
  0x4a8655、0x4a8a8c。**加入时没有任何容量检查**，内存里无上限。
* 处理：每日更新 0x4a1880 遍历列表（任务 0 = 移动：到达目的建筑就清任务；见 0x4a18d2..）；0x49f430/0x49f4e0 等按势力、任务号在列表里找武将；
  0x483440（读档后 0x4a199f/0x4a1bc6、0x59a081）删掉 +0x13C 不在 0..43 的项；0x482f20 找第一个空闲任务的武将。
* 写档（0x483311..0x48337c）：栈上 1000 个 dword 先全填 −1，按链表顺序把前 1000 个指针换成编号（0x491310），
  然后 1000 × i16 写出（2000 字节，头 2212 字节的大头）。**超过 1000 个的部分静默丢掉。**
* 读档（0x483380..0x4833bd）：读 1000 × i16，0..1099 的经 0x490b00 取指针后 push 回链表。
* 栈帧 `sub esp,0xfa4`（0x483120）正好装 1000 dword。

**会不会超过 1000**：会。原版里特殊武将（1000..1099）不接任务，可用武将 ≤ 1000，所以 1000 永远够。
P 名武将时，同时在途（移动）或执行任务的武将数上限是 S+150（可用武将数）。P = 5000 时 AI 大量调动武将，超过 1000 是现实的；
超出的武将存档后不在列表里，但 +0x13C 仍保留任务 → 读档后不再被每日处理（移动中的武将永远到不了）。

**处理建议**：
* 最省事：读档后不用文件里的列表，改为从武将表重建（凡 +0x13C 在 0..43 的武将按编号顺序 push）——任务字段已经在武将记录里存档
  （0x48baaa 写 +0x13C，0x48bab8 写 +0x140..）。写档仍写 1000 项（兼容）或改成"项数 + N 项"。需要确认列表顺序是否影响处理顺序
  （只影响同日处理先后，不影响正确性 [?]）。
* 若保留文件里的列表：容量 1000 → S+150（或 P），栈缓冲改到 DLL；文件格式变（头里加长度），i16 限制 P ≤ 32767。
* 0x483398 的 `cmp 0x44b` 已在常量审查里（PERSON_MAX）；0x483089/0x48335f/0x48336b/0x4833b7 的 1000 是本列表容量（不是 S+150 的常量含义，
  要随上面方案改，不能简单换成常量表达式）。

## 3. 其它按武将编号的全局/静态数组

扫描方法：(a) 全部 `imul/add/sub ...,0x190`；(b) 从 0x491310（指针→编号）的结果、传给 0x490b00/0x412390 的寄存器、`cmp reg,0x44b/0x44c`
的寄存器向前/向后追踪 30 条指令，找以它为下标（`[reg*N+disp]` 或 `[reg+abs]`）的内存访问；(c) 世界里 type 18 / AI 段的绝对地址引用。

结果：**没有发现常量审查之外的新数组。** 命中的全部是已知项：
* 0x4aefc9、0x4b01ed、0x4b0481、0x4b23e9、0x4b2415、0x4b24b8、0x4b24e1（两个平行 int[1100]，M10 §4.3）；0x4b2a16（栈上同布局，§4.2）；
* 0x58d2a6、0x58d582（vt 0x84b09c 对象 +0x180 int[1100]，§4.2）；
* 0x69a2bf、0x69a6a9（武将快照类 +0x58164 标志，§4.3）；
* `0x190` 的其它用法（0x5f0e29、0x5f1582、0x5988fe、0x5eddca、0x607fa2、0x60eabf、0x610748、0x5a9a5f 等）都是数值 400 或别的结构偏移，与武将表无关；
  搬表相关的 0x4910bb/0x49110d/0x492a4e/0x493437/0x493831 已在 §4.1。

存武将编号（不是按编号开）的静态表，全是光荣写死的 0..849 内的编号，**不用改**：
0x83d378（700..713，0x52aa01）、0x8b877c/0x8b8784（0x3c 步长记录，0x546ce0）、0x8b9a98（0x5cf180）、0x8c2954/0x8c2958（12 字节记录，0x693455）。

只在内存的临时结构（不进文件）里也有 32 位武将字段：事件描述 0x47f220..0x47f2e4（+8）、开局/界面对象（0x534ee0、0x539710、0x53ba20 的 +0x1e8/+0x1ec/+0x1f0/+0x200/+0x4f4，
0x615250 +0x21c，0x55baf0 +0x190，0x5842d0 +0x18，0x5410a0 +0x1c/+0x38，0x684562 +0x10/+0x14），都是 int，宽度不成问题。

## 4. 顺带发现

* 审查结果里 0x48d9ad 的备注写成"武将配偶/义兄弟 +0x60/+0x64"，实际是**关所/港的太守字段 +0x64** 的 setter（patch 仍是 P−1，不影响补丁）。
* 系统存档（0x4941F0，world+0x1F9BB4）不在本题范围，但 world+0x1f9dc4（150 × 0x20，按 id−850，getter 0x490f00）在它里面，M10 §4.4 已记。
* 头 +0xC4 的 47 个 dword（写成 u8）是"玩家槽 → 势力"表（0x482610），不是武将。
