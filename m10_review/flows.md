# M10：扩展武将（850..S−1）相关流程的静态分析

范围：M10_PERSONS.md §4.4/§4.5/§4.7 的待查项。只做静态分析（pk.asm），没有运行游戏。
记号：S = 剧本武将数，P = S+250；"扩展武将" = 850..S−1；"新武将" = S..S+149；"特殊武将" = S+150..P−1。
武将状态 +0xa0（由谓词 0x488c00..0x488c80 得出）：0 君主、1 都督、2 太守、3 一般、4 在野、5 俘虏、6 未登场、7 未发现、8 死亡。

## 1. 列传（biography）和台词

### 1.1 现在的流程：0x48e850 `GetBiography(str, person)`
调用者：0x529df6、0x6299ae、0x68e898、0x693930。

```
id = 0x491310(person)              ; 指针 → 编号
0..699    → msgid = 10000+id       ; 0x48e88f / 0x48e897
700..799  → msgid = 10000+id       ; 0x48e8ab..0x48e8c8（实际只有 700..724 有正文）
800..849  → msgid = id+9925        ; 0x48e8cf..0x48e8df（lea eax,[esi+0x26c5]）→ 10725..10774
其它      → 0x488250(id) 判断 850..999（新武将）
             → 0x490ea0(id) = world+0x12c092+id*0x247 = 新武将编辑记录（world+0x1A5050 起，150×0x247），
               记录开头就是列传字符串，0x471ac0 直接追加
```
0x48e89d..0x48e8f5 那串 `cmp 0x2710/0x29ad/...` 编译后等于 "msgid≠0 就用"，不是范围限制。

**消息资源**：`media\msg\S11MSG??.S11`（模式串 0x7e7370，加载器 0x499740 起枚举两个目录：先 vcall+0x14 给的目录，再 media\msg；
文件号由文件名 ?? 解析，最多 30 个块，0x499830/0x499966 `cmp 0x1e`）。查找 0x4976a0：`块号 = msgid/5000，块内序号 = msgid%5000`
（`div 0x1388`），块号匹配 [节点+4]，序号 < 块内条数（[节点+8]）才有效。
文件格式：LS11 压缩（"LS11"+12 字节、256 字节字典、(压缩长,原长,偏移) 大端表、位流），解出来是 `u16 条数 + u32 偏移[] + 文本`（cp950 繁体，
带 \x02..\x05 控制码）。解压脚本在 scratchpad `m10\ls11.py`。

实测 S11MSG02（块 2，2428 条）：
| 序号 | 内容 |
|---|---|
| 0..669 | 武将 0..669 列传（0 = 孟获部下"第三洞元帅"= 阿会喃） |
| 670..699 | 空（"\x05\x05\x05"，对应光荣空槽 670..699） |
| 700..724 | 事件/异族头目列传（700 = 汉灵帝…724 = 贼） |
| 725..774 | 古武将 800..849 列传（725 = 孔子） |
| 775.. | 名将列传、事件说明、名言、帮助等 |

块内 5000 条上限 + 块 2 已经被其它内容占到 2427，所以"列传最多 1000 条"不能原地扩；**扩展武将在原版代码里走 ≥850 分支，
常量改成 S 以后 0x488250 返回 0（850..S−1 不是新武将）→ 列传为空**（不会崩）。

### 1.2 台词（话痨）
没有找到按武将编号查消息号的第二张表。S11MSG01（3804 条）/S11MSG03（3934 条）是对白库，按场景和语气选取；
对特定武将的特殊台词是写死编号的 switch（例：0x581140 对 700、701… 的 switch，0x5806fb），都在 0..849 内，不受影响。
扫描所有 `push <计算值>; call 0x49cb60`（消息对象构造）的地方，除 0x48e8f7（列传）和 0x48f885（物品说明 0x2b84+id）外没有按武将编号算消息号的。
结论：扩展武将用通用台词，不需要改。（置信度中等：消息号也可能经其它包装函数传入，未逐一追踪。）

### 1.3 建议补丁（列传）
两种做法，都只改 0x48e91e 一处：

**A. DLL 直接给文本（最小）**
0x48e91e `56 e8 2c 99 ff ff`（push esi; call 0x488250，6 字节）→ `jmp cave; nop`：
```
cave: cmp esi,850 ; jl  orig
      cmp esi,S   ; jge orig
      push esi ; call dll_ext_bio ; add esp,4      ; const char* dll_ext_bio(int id)，cp950/游戏内码，可带控制码
      test eax,eax ; je 0x48e942
      push eax ; mov ecx,edi ; call 0x471ac0 ; jmp 0x48e942
orig: push esi ; call 0x488250 ; jmp 0x48e924
```
**B. 走消息系统**：DLL/工具生成 `S11MSG04.S11`（块 4，msgid 20000..24999）、需要时 05、06…，扩展武将 msgid = 20000+(id−850)
（跨块连续，因为 块=msgid/5000）。cave 改成 `lea eax,[esi+20000-850]; jmp 0x48e8f7`。好处是文本走原来的格式化；
要先在运行时确认加载器确实会收新文件号（0x499740 枚举 + vcall+0x1c 解析文件号，静态看是这样）。

## 2. 头像

* 字段：武将 +0x3C（剧本加载 0x48b7f0 读入）。取头像 0x48a450（84 处调用）：
  `face = +0x3C；若 0..2399 且 头像表[face].flags & 2（存在）→ face；否则 0x49d730(+0x40 性别) = 男 2000 / 女 2100`。
* 头像表：0x6fae8b8，2400 × 4 字节（上界 0x95f 在 0x48a457、0x4802a8 等处），字节 3 bit1 = 有图。
  加载 0x46e360 起：`media/face/San11Face00.fce`（另有 San11ChangeFace.fce、模式 San11Face??.fce），头 0x14 字节
  （"FACE"、版本 0x40 ≤ 0x64、起始号 +8、条数 +0xC），后面依次是 4 字节信息表、8 字节表……按起始号写进 0x6fae8b8。
* 本机文件：San11Face00.fce 2200 槽（社区改过，2019），有图 1220 个：0..699、700..999 中零散、1001..1566 零散、1786..1799、2000..2173；
  原版 San11Face00-old.fce 也是 2200 槽、964 个有图。
* 0x485fc0（新武将对象 vt 0x79c698 的 +0x20"重置"）把 +0x3C 设为 2000（0x485ff0），这是新建/重置新武将时的默认，和扩展武将无关。
* 选头像对话框（"選擇容貌"，0x549xxx）列出 0..699 武将的头像（0x5493f0..0x549447，`(face+1000)%2000` 有图）和 0..762（0x549360..0x5493dc）。
* **结论**：头像号与武将号无关，多个武将可共用同一个头像号；没发现按头像号反查武将或要求唯一的代码。扩展武将剧本里直接写现有头像号
  （或 2000/2100 通用）即可。专属新头像只受 2400 上限和 .fce 文件制约，与 P 无关。

## 3. 登场与槽位分配

### 3.1 0..849（含扩展武将）按年登场
* 0x59e4b0（被 0x59e951 调用，每回合/每年）：`for id in 0..1099`（0x59e53d，PERSON_COUNT，已在审查里）：
  `0x488c50`（状态 6 未登场）且 `当前年(0x4824b0) >= +0x44（登场年）` → 收进列表，0x4ced10 排序后交 0x588d70 处理。
  只按状态和年份，**不看编号**，扩展武将改了常量后自动参与。
* 0x4a5b20：状态 7（未发现）→ 4（在野）并放到地点（事件/脚本 0x5d5703、0x670208 调用），也不看编号。
* 剧本读入 0x48b760：`id >= 850 → 跳过`（0x48b787，SCEN_COUNT → S），扩展武将跟 0..849 一样从剧本读。

### 3.2 新武将 850..999（→ S..S+149）
* 数据：world+0x1f9dc4 的 150 个 0x20 字节对象（vt 0x79c698，构造 0x4857c0；+0x28 取编号，+0x3c/+0x40 取武将，+0x48 取编辑记录 0x490ea0），
  按 id−850 取 0x490f00；指针→编号 0x491810（+850）；找空槽 0x491130。编辑记录 world+0x1A5050，150 × 0x247，按 id−850（0x490ea0）。
* MakeData：`SaveData\MakeData.s11`（串表 0x8a5814）读写 0x43bdf0/0x43be70 → 0x43ab90：`for id in 850..999: 0x490f00(id)->vt+0x30(serialize)`
  （0x43abad/0x43abca 已审），之后 50..99 的物品编辑（0x490f30）。每个对象序列化武将字段 + 0x247 编辑记录（vt+0x30 = 0x486250）。
  TPrsn\*.s11 导入单个新武将用同一套对象（0x491130 找空槽）。
* 开局：0x4a42d0（新游戏初始化，0x4a5051 / 0x52e01b 调用）里 0x4a4473..0x4a44b6 处理古武将 800..849，0x4a44be..0x4a4532 处理新武将
  （0x4a2490 按开局设定决定登录，否则 0x4898f0(-1)）。
* 这些全部是 850/999 常量（已审，→ S / S+149），扩展武将不进这些循环——正确，扩展武将是剧本武将。

### 3.3 特殊武将 1000..1099（→ S+150..P−1）
* 0x491090 找第一个空（vt+8 返回 0）特殊武将：`esi=1000; edi=world+0x6db3c(=武将表+1000×0x190)`，循环到 `esi−1000 < 100`（0x4910c2）。
  唯一调用者 0x4aa610（建特殊武将：0x4a98c0 初始化、状态 4、地点 −1，再 0x4a31e0/0x4a0cb0、0x492990）；0x4aa610 被 0x4af1f1、0x677719 调用。
* 0x4910e0 数空的特殊武将（0x58e858、0x58eaf9 调用）。
* 两处 `lea edi,[ecx+0x6db3c]`（0x491097、0x4910ea）是 §4.1 已记的漏收位移，其余都是已审常量；没有别的假设。

### 3.4 "剧本段到 850 为止"的常量以外的假设（重要）
1. **"史实武将 0..699"谓词**：扩展武将改完常量后不属于任何一类（史实 0..699 / 事件 700..799 / 古 800..849 / 新 S..S+149 / 特殊）。
   * 0x489c60 `isHistorical(person)`（11 处调用）、0x488230 `isHistorical(id)`（1 处：0x48d692）。
   * 调用方大多是"史实 ∨ 新 ∨ 古 = 普通武将"过滤：0x4a28c2/0x4a2937/0x4a29b6（武将死亡时整理亲近/厌恶名单）、0x6a22d9/0x6a2629（快照类）、
     0x53d131/0x53d375（史实 ∨ 新）、0x66fc4d（脚本属性"是否史实"）、0x531a62（沿血缘链上溯）。扩展武将会被这些地方漏掉。
   * 0x495110 `validOfficer(id)`（0..699 ∪ 800..849 ∪ 850..999 ∪ 1000..1099，排除事件武将），唯一调用 0x49587c（某对象两个武将槽的 setter）。
   **建议**：把 0x489c60、0x488230 改成 "0..699 ∪ 850..S−1"（见 §5.2 的 cave）；0x495110 只改一个常量：0x495126 `cmp eax,0x351` → S−1
   （区间变成 800..S−1，正好 = 古 + 扩展），配合审查里 0x49512d/0x495134 的 S/S+149。
2. **"800..999"合并区间**（古 + 新）：常量审查把 999 改成 S+149 后，区间变成 800..S+149，**把扩展武将也框进去**，
   而这些地方后面会用 id−800 取 200 项的开局设定表（§6）→ 越界。必须拆成两段，见 §6.3。
3. 列传（§1）。
4. 编辑器/界面里只列 0..699 的地方（§4、§5），扩展武将不显示，属外观问题。

## 4. 界面列表

* **列表容器**（vt 0x79bf44 / 0x79bf34，push_back 0x47c1b0）：动态链表，每块 10 个 12 字节节点，块从全局位图池分配
  （0x47c090 → 0x472e80(…, 0x6ee7950, 0x10000)：65536 块 × 0x7c 字节，池满后 0x472e53 退回 malloc）。
  单个列表上限 65536 个元素（0x47c0e5 `cmp [ecx+0xc],0x10000`）。P ≤ 30000 没问题。
* **列表控件**：加一项 0x4dd0b0 → 0x4e6340（vt+0x1e8 分配节点，链表在控件+0xb0，计数 +0xbc），动态，没看到容量上限。
* 武将列表的构造都是"循环所有武将 + 过滤 + push_back"（例：0x4cf650..0x4cf7ae，0..1099，跳过 700..799 事件武将；0x4cf7d0 新武将列表；
  0x4cf820 古武将 + 新武将列表）。随常量自动扩大。
* **固定容量的只有**：
  * 武将快照类（vt 0x862d28，§4.3 已记）：选择武将对话框 0x69ae90 用它。例：0x622bb0 栈上构造（帧 0x59298），0x69a410 → 0x69a450 填
    `for id in 0..1099`（0x69a48b），0x69a4a0 按编号取 `id*0xa4`（上界 0x69a4b0）；对话框返回的编号在 0x622c28 检查 0..1099。
    这正是"0x622c28 对话框"——容量来自快照类，不是列表控件。
  * §4.2 的栈数组（0x5c7dc6、0x5c8bb6、0x5c97bc、0x590490、0x4b2820、0x4b7e70），已记。
* 只列 0..699 的界面（扩展武将不出现，可选修改）：
  * 0x52a970（编辑器"登录武将"类列表，0x52abea 调用）：0..699 史实（0x52a982..0x52a9be）+ 800..849 古武将 + 0x83d378 的 14 个固定编号。
  * "選擇容貌"对话框（串 0x7f118c）：0x549360..0x5493dc（0..762）、0x5493f0..0x549447（0..699）、0x549c55..0x549c89（0..699，进列表控件）。

### 5.2 补丁形状
**谓词（0x489c60，ptr 版）**：0x489c6f `3d bb 02 00 00 7f 06`（7 字节）→ `jmp cave; nop; nop`：
```
cave: cmp eax,0x2bb ; jle T          ; 前面已有 test eax,eax / jl F
      cmp eax,850   ; jl  F
      cmp eax,S     ; jge F
T:    mov eax,1 ; ret
F:    xor eax,eax ; ret
```
0x488230（id 版）同理，改 0x488238 处 `3d bb 02 00 00 7f 06`。
内联判断（0x4a268b、0x4a4638、0x4a4669、0x4a479c、0x4a47dc）都是 `cmp r,0x2bb; jg X`（6+6 或 5+6 字节）→ jmp 到同样的三段比较，失败跳 X，成功跳回下一条。

**循环（"0..699，再 850..S−1"）**：每处都是 `inc r; cmp r,0x2bb; jle top`（或 `cmp r,0x2bc; jl top`），换成 jmp cave：
```
cave: inc r
      cmp r,700 ; jne 1f
      mov r,850
1:    cmp r,S   ; jl top
      jmp after
```
栈上计数器的变体（0x4a480e：`mov eax,[esp+0x60]; inc eax; cmp eax,0x2bb; mov [esp+0x60],eax; jle`；0x4a4b46 同理）在 cave 里照抄存回。
S=850 时 cave 的第二段是空的，行为与原版相同（回归测试友好）。

## 6. 两张"id − 800"的 200 项表

### 6.1 它们是什么
两张其实是**同一个结构**——"开局/登录设定"（古武将、新武将要不要登场、在哪个势力、在哪个城）：
* 结构 0x10a8 字节（0x557460 用 `rep movsd ecx=0x42a` 整体拷贝）：+4 势力 8×0x1c，+0xe4 城市 42×0x14，**+0x428 武将表 200 × 0x10**
  （0x428+0xc80 = 0x10a8，表正好在结构尾）。表项 `{+0 状态, +4 势力, +8 地点(城/据点), +0xC 另一个地点/编号}`，下标 = id−800，
  覆盖 800..999（古 50 + 新 150）。
* 从当前世界生成：0x551460（唯一调用 0x55749b，0x557460 里，栈上）。表项循环 0x5516c0..0x551746，`lea eax,[edi+0x320]`，上界 0x551740 `cmp edi,0xc8`。
* 应用到世界：0x54e040（表指针在 eax）`for idx 0..199: 0x4a0740(person(800+idx), 状态, 势力, 地点, 城)`；0x54e0f0（结构指针参数）。
  0x555f50 里 `0x54e040(this+0x28d8)`、`0x54e0f0(this+0x24b0)` → 这个界面类把结构嵌在 **this+0x24b0**，表在 **this+0x28d8**。
* 另一个界面类（0x5539f0、0x553b40）把表放在 **this+0x24ac**（初始化循环 0x553a11..0x553a32，上界 0xc8 两处 0x553a17/0x553a2d）。
* 名单来源 0x4cf820：古武将 800..849（0x49d6e0 判定可用）+ 已建的新武将（0x490f00），所以这些界面里的武将编号只会是古/新武将。

所以审查里的"开局设置结构 +0x428"与"快照对象 +0x24ac/+0x28d8"是同一布局的不同实例；结构大小固定，**保持 200 项、只改下标映射**最省事。

### 6.2 映射
引入"虚拟编号" v：古武将 800..849 → 800..849，新武将 S..S+149 → 850..999（v = id<850 ? id : id−(S−850)）；
反向 id = v<850 ? v : v+(S−850)。在每个"拿到编号 → 算下标"的点先把编号变成 v，在每个"下标 → 编号"的点把 v 变回编号，
原来的 `−800`、`−0x2dd`、`−0x2dd8`、`−0x928`、`+0x24b` 算式都不用动。S=850 时两者都是恒等。
