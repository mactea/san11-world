# 特技组合

worldmod 可以把多个原版特技的效果组合成一个编号。武将仍然只有一个特技字段，剧本和存档的字段长度不变。

## 启用

编译 `worldmod/build.bat`，通过工具包正常部署 DLL。部署会在游戏目录缺少 `worldmod_skills.txt` 时复制示例配置；更新时保留已有配置。

在游戏目录的 `worldmod.ini` 中，为需要启用的启动程序添加：

```ini
[san11pk_world]
skill_combos=1
```

默认关闭。`[mod] verify_only=1` 时会检查配置和补丁指令，但不会安装组合特技补丁。

## 定义组合

编辑游戏目录里的 `worldmod_skills.txt`，保存为 **UTF-8**。每行格式是：

```text
编号|名称|说明|组成效果编号，以英文逗号分隔
```

例如随附配置：

```text
100|明略|虛實、名聲、發明|57,79,82
101|神膽|遁走、騎將、強行、長驅、洞察|1,37,2,3,61
102|清談|機智、名聲、論客|55,79,86
108|仁德|伯樂、遁走、眼力、名聲|146,1,85,79
147|商才|商隊加倍，費用八折，異地售貨正毛利加兩成，不疊加|147
```

- 新组合编号为 **100～249**。名称必须填写，组成效果必须有 1～8 项，每项可以使用原版 **0～99** 编号，以及已实现的 **146 伯乐**、**147 商才**。
- 可以定义原版 0～99 编号，为它追加效果；它自己的原版效果始终保留。
- 不支持嵌套组合。已实现 146 伯乐的跨城登用效果（相性差不超过 25）及 147 商才的所在城自动商队上限翻倍效果；其它 SIRE 扩展效果没有移植，不能作为组成项。未使用的这些编号在 worldmod 中可以用作自定义组合编号，两套配置不通用。
- 名称、说明用游戏 Big5 字库支持的文字（通常用繁体），分别最多 **4、66 个 Big5 字节**，即最多 2、33 个汉字。UTF-8 文件会在加载时转换为 Big5；名称遵循原生特技短名字段的长度。
- 不要在字段中使用 `|`，不要给编号加空格。空行和以 `#` 开头的注释行会被忽略。
- 编号重复、效果编号越界、文字无法转换、字段过长等都会拒绝配置，在日志中指出出错行。所有补丁写入前会核对原始指令，防止覆盖其它修改器。

改动后重启游戏生效。配置不会嵌入存档；分享剧本或存档时应一并提供配置。

商才的驻城条件、名额计算和建议人物名单见[商才特技与自动贸易名额](商才特技与自动贸易名额.md)。147 可以独立赋予，也可作为组合效果；多人驻同城只加倍一次，组建与续航费用减两成也不叠加。本次人物分配仅赋予无特技者，已有特技原样保留。

## 给武将赋予组合

在剧本 JSON 的新武将对象里添加 `skill`：

```json
{"name":"凱撒","city":"敦煌","skill":100}
```

这只是字段示例；在现有武将对象中添加 `skill`，保留他的其它设置。然后重新编译剧本：

```powershell
python san11kit.py scenario scenarios/europe_184.json
```

新开局会读取修改后的剧本；已有存档不随剧本修改。已有存档中的武将如果已经持有该编号，重启后会按新的组合定义判定效果。255（文件）/ -1（内存）仍表示无特技。

本版本通过剧本中的编号赋予新组合，**没有把新增组合加入原生编辑器的特技下拉菜单或研究树**。原生特技总数和原版数据序列化保持不变；已经赋予的新组合通过资料查询接口提供名称、说明和编号。类别、等级沿用第一个组成效果的原版资料，不能单独配置。

各原版效果仍遵循自己的触发条件。例如把骑将、发明组合到一起，不会让骑将对所有兵种生效；没有另外添加 SIRE 的兵种匹配规则、宝物附加特技或伯乐的月初推荐事件。

## 研究进度解锁（2026-11-08）

`worldmod.ini` 对应游戏节设 `research_progress=1` 后，每个常规势力独立按48项固定能力研究的完成数解锁，玩家与电脑同规则。隐藏研究不计入进度。

| 已完成固定研究 | 隐藏研究位置上限 |
|---|---:|
| 0～11项 | 5 |
| 12～23项（25%） | 6 |
| 24～35项（50%） | 7 |
| 36～47项（75%） | 8 |
| 48项（100%） | 10 |

保留原有隐藏选择，只在尚未分配的位置确定一个该组原生研究项目；首次确定后使用原生势力字段保存。新项目仍须满足原有前置研究、花费资金和研究时间。检查研究列表或研究资格时生效，不自动标记研究完成。

特技传授额度独立按当前实际占领的城市数增长，不使用研究进度。少于20城为第0阶段，20／40／80／100城分别为第1／2／3／4阶段；关隘、港口及其他势力城市不计入。最终总额度为S档3次、A档10次、B档20次、C档30次。计算为 `原额度 + floor((最终额度 - 原额度) × 阶段 / 4)`；最终额度不低于原额度，因此原本5次的S档仍为5次。使用与名单一致的原版100种特技评级。例：原3次的A级连击，五阶段总额度为3／4／6／8／10次。基础能力和兵种适性培养次数不调整。

剩余次数为当前城市规模对应的总额度减去已消耗次数，最低为0，不因过旬、重启、读取存档重复补满。丢城后额度下降，但不删除武将已经学会的特技，也不清零已消耗次数；夺回城市后仅恢复尚未使用的额度。旧存档按已完成研究解锁隐藏位置、按当前城市数计算传授额度，无需重开；首次解锁后正常保存即可保留新增选择。未研究的项目不能直接传授，学习仍会覆盖武将已有特技。商才、伯乐和新增组合不因此进入研究树。

实现为 `worldmod/src/research_progress.cpp`，核对八处原版指令后整体安装。`worldmod/test/build_research.bat` 编译独立运行测试，覆盖门槛、各势力隔离、扩展势力编号、额度消耗、原有选择、基础培养不变、四种x86调用约定适配和错误指令拒绝；`tools/verify_research_progress.py` 独立核对真实exe、主数据研究记录及名单评级。未宣称完整游戏界面端到端测试。

## 特技事件 CSV（开发中）

在对应游戏程序的配置节中同时设置 `skill_combos=1` 和 `skill_telemetry=1`，重启后启用记录。只有特技补丁安装成功才会打开日志；启动日志应出现 `skill telemetry: enabled`。默认不记录，设 `skill_telemetry=0` 可关闭。此开关不修改剧本或存档。

文件写入游戏目录的 `skill_logs/skills-日期-时间-进程号-启动计数.csv`，每次启动单独建文件，采用带 BOM 的 UTF-8 和36列固定表头。记录包括游戏日期、场景、事件、武将编号与中文姓名、持有特技与实际组成效果、势力、君主、目标、资源变化及 JSON 上下文。

- `stage=check_matched` 仅表示判定匹配，包括界面或电脑估算，不能算作实际触发。按实际触发统计时筛选 `stage=applied`，再按 `event`、`scene`、`person_id`、`force_id` 和 `effect_skill` 分组。
- `owned_skill` 是武将持有的编号；`effect_skill` 是本次生效的组成效果编号。同一组合可以产生不同组成效果的记录。
- `actor_city` 只表示武将当前实际位于的城市。出征、关隘、港口及其他非城市位置记为 `-1`，不把部队位置或所属据点冒充当前城市。其他未知实体编号为 `-1`，未知游戏日期为 `0`。
- `before/after/delta` 按 `metric` 表示实际资源、原生运算或状态变化；存在可验证的局部无特技基线时，另写 `baseline_after/bonus_delta`。缺少可测数值时留空，不能把空值补成零。
- 一次行动可能记录多个判定、组成效果或资源写入。24／50共同作用的整次伤害以 `context_json.shared_resource_write_id` 关联；两行中的整次伤害不能相加为额外伤害。
- `ironwall_capture_multiplier_reduced` 表示铁壁在原生俘虏抽样中把包围倍率压到100，记录包围数量、实际抽样概率和结果，不表示已经逃脱。数量为1时只有查询记录；与捕缚同时生效时，最终概率仍可能为100%。
- `lucky_capture_attempt_skipped` 表示强运让原生流程跳过该武将的俘虏抽样。宝物已先行保护时不重复算强运；它也不是整个战败处置已经结束的记录。
- `casualty_selection_blocked`／`casualty_candidate_excluded` 分别记录护卫阻止伤亡选择、强运排除个人候选。`selection_scope` 区分普通战死、普通负伤、战法负伤、战法战死；它们不表示已经避免一次必然死亡或负伤。直接调用选择器的查询不计作效果。
- `fire_casualty_processing_skipped` 记录回合更新时护卫或火神使部队跳过原生火灾伤害处理；护卫优先，火神不会重复计数。只有回合处理调用完成后才记录，直接查询或预览不计作实际效果，数值栏保持空白。
- `trap_damage_modifier_settled` 在陷阱伤害实际写入后，记录火神、藤甲、踏破各次原生伤害运算。`calculated_trap_troop_damage`／`calculated_trap_hp_damage` 是该步计算值；`context_json` 的 `resource_before`／`resource_after` 是整次实际兵力或耐久变化，包含额外火伤和上限影响，不能将多条计算行当作多次损失相加。原生调用归属、武将身份、所属及部队状态失效的记录，以及普通和结算中嵌套的预览，都不计作实际效果。
- `vine_physical_reduction_settled` 记录藤甲在主攻击伤害路径中的原生减半运算。`calculated_physical_troop_damage` 保留减半前后值；后续系数处理后的伤害和实际兵力前后值另放在 `context_json`，所以计算中减少的伤害不等于最终少损失的士兵。该记录随伤害包复制、过期，只有匹配的真实写入才产生效果行。
- 藤甲的反击记录保留原生 `native_attack_mode`，并跟随已验证的人数系数写入及附加字段转存进入结算。它与突袭／强袭的免反击效果各自记录；人数系数不算作藤甲再次减伤，未观察到的伤害改动仍会使归属记录失效。
- 藤甲观察点位于原生减半运算处，保留“无藤甲”分支的跳转入口。该分支的144组对照应保持原有伤害且不产生藤甲事件；另有原始程序直接分支／调用入口检查，检查范围不包含间接跳转或运行时生成代码。
- 辅佐攻击中的藤甲减伤同样使用 `vine_physical_reduction_settled`，`record_kind=3`；该构造函数没有独立攻击模式参数，因此 `native_attack_mode=-1`。关系触发的追加攻击可以产生藤甲事件，但不会据此生成“辅佐”特技事件。
- 辅佐攻击中的不屈／金刚免伤使用 `damage_immunity_assist_attack_settled`，同样标记 `record_kind=3`、`native_attack_mode=-1`。仅在原生判定写入免伤标记、伤害归零且真实兵力结算发生后记录；失败抽样只有查询行。免伤和之后可能执行的藤甲分别记录，零伤害上的减半不表示再次救下士兵。
- `aggregated_attack_component_settled` 保留多条攻击合并结算时各组成特技的实际来源。按同一CSV中的 `(pid, context_json.aggregate_settlement_id)` 关联整次结算，`component_index` 区分攻击记录，`component_role` 区分同一记录的暴击、免伤、藤甲等作用。免伤和藤甲记录原生运算前后值；其他作用的 `settled_component=0→1` 表示该组成已进入真实结算。`shared_resource_before/after` 是整次兵力写入，不能在多行之间相加，也不表示每个特技独立造成的兵损。缺少可靠来源的组成不猜测归属。
- `scene=ai_evaluation` 的 `strategy_role_weight_selected` 记录AI角色计算中原生权重由524变为1024的一步，`calculation_only=true`。八种特技按百出、神算、火神、鬼谋、连环、妖术、鬼门、深谋的原生编号顺序检查（64／63／62／65／66／70／71／67），首个匹配项提供一次权重，多个特技不叠加。按此场景统计AI评估次数；计略行动次数按对应行动事件统计。最终AI选将、施法结果和其他评分项不在这条记录中。

实际效果记录会立即刷新到文件；查询记录在后续写入时按一秒间隔刷新，关闭日志时也会刷新。写入失败会在启动日志报 `CSV write failed` 并关闭记录，游戏逻辑继续执行。

新版允许游戏运行时只读检查CSV，仍禁止其他程序同时写入该文件；读取时应只处理完整的行。

目前100种原版特技均有部分效果埋点，另有伯乐、商才及组合特技路径，**不代表全部场景已经覆盖**。2026-11-10已将通过独立原生代码测试的258个埋点部署到正式游戏，并启用日志开关；保留现有缓存修复外壳，仅更新 `worldmod_core.dll`。正式安装的初始化检查确认CSV创建成功、36列表头完整，6份存档未变化；该检查在读档和菜单操作之前结束，已读取旧版正式日志中的内助属性刷新事件，读档后的行动事件尚未验证。下一次正常启动游戏并读档后即可开始记录，真实游玩事件和游戏内性能仍待验证。备份及部署校验见 `outputs/skill-telemetry/deployment.json`，正式初始化记录见 `outputs/skill-telemetry/installed-runtime-smoke.json`。覆盖范围与待办见 `outputs/skill-telemetry/coverage.json`，最近验证记录见 `outputs/skill-telemetry/verification.json`。

妖术逐个目标的原生命中判定另记录洞察61、看破60的免疫，以及虚实57、神算63的必中或免疫。日志区分 `magic_target_immunity_forced_failure` 与 `magic_target_forced_success`，归属原生查询实际选中的第一名武将，保留双方部队、势力和智力。它们是命中判定事件，后续混乱、伪报的状态写入单独记录；不推算额外收益，也不重复抽取随机数。原生顺序为先洞察，再按双方智力检查虚实／神算或看破／神算；智力相等时继续原有随机判定。直接预览没有指令归属时，只记录查询。

扰乱、伪报与伏兵的异常状态结算新增 `strategy_critical_status_written`，将已确认的强制暴击与实际状态、持续回合的写入关联到同一武将。覆盖妙计58、秘计59、神算63、深谋67，以及伏兵中的待伏16。记录原生请求回合与写入前后数值，包含已达回合上限的真实结算；不估算额外回合。读档、武将归属、部队成员或目标位置变化后，旧关联失效。

伏兵的强制计略暴击还会沿实际伤害包传递到扣兵结算，新增 `strategy_critical_ambush_troops_written`。记录本次伏兵造成的实际兵力变化，包含兵力不足与零兵力的原生截断；不将整次伤害解释为特技的额外伤害。混合包汇总时，只记录已证实来源的分项参与结算，把共享兵力余额放在上下文中。伏兵返回时清理源包归属，未登记来源的相同字节包不会继承归属。

商才147另记录成功支付的运费折扣（`merchant_departure_fee_discount_committed`）和真正使用额外自动商队名额的创建（`merchant_extra_caravan_slot_used`）。报价、失败出发与退款不记作已生效；商才本人带队离城的正常变化保留本次归属。成交加成保留货物、数量、成本、税款、旧债与加成金额，`sale_payout` 包含国库已满时保留的待入库收益。运费指标 `trade_fee` 表示已支付费用中的折扣计算，不表示整个国库余额变化。

## 实现与验证

`worldmod/src/skills.cpp` 负责配置、Big5 转换及十处补丁：武将判定、赋值、部队判定、资料查询、资料地址转编号、排序顺序、武将列表排序字段、特技字段读写、收入类特技汇总和伯乐跨城登用筛选。部队判定沿用原生的成员查找，不依赖固定武将数组或 1099 上限。

收入汇总单独展开原版组成效果，补齐富豪、米道、征收、征税这一条不经过普通武将特技判定的路径。128～249 号的读档修正只作用于武将特技字段，其他有符号字节字段不变。

测试命令（需要 Visual Studio x86 C++ 工具和本地支持版本的原版 exe）：

```powershell
worldmod/test/build_skills.bat "C:/San11PK/san11pk.exe"
```

测试从 exe 读取实际指令，在独立进程的代码缓冲区验证并执行补丁分支，覆盖配置错误、组合与无特技判定、超出 1099 的武将编号、名称/编号查询、排序、收入汇总和 128～249 的字段往返。底层流 I/O 和收入列表遍历使用桩函数；这些测试不等同于完整游戏界面及完整存档文件的端到端测试。
