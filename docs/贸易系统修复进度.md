## 已写入代码

- **有限库存**：按城市、商品保存库存，买入扣库存、售出补库存。非产地可以转售运来的货物，但不会自行生产。月度生产、消费、仓储上限来自 `data/trade_goods.json` 的 `inventory`；当前默认上限为市场规模的 200%，产地初始 100%，枢纽进口初始 10%。
- **统一成交价格**：买卖共享逐担价格轨迹，商人折扣只缩小双边价差，不再制造买卖倒挂；保留最小价差。拆单和整单的价格轨迹一致。库存或库容不足时整笔拒绝，玩家可自行减少数量。`trade_revert=0` 不再发生隐式回归。
- **真实资源支出**：出发从己方出资城扣金、护卫和兵粮；原生出征失败时恢复库存、价格及预扣资源。商队在首次行动前登记，首次行动中被击破也能识别。结束行程仅归还剩余兵粮、兵力；城市容量不足的款项和资源保留为待入账记录。
- **多商品和多站交易**：货物按商品、采购城市保存数量及成本。到站停靠，支持部分买卖、继续前往下一城；卖出所得立即汇回出资城，原城失守时改用最近同势力城市。只能与非敌对市场交易。仅在己方城市补充兵粮；不会在外国城凭空补兵。结束时有余货须明确确认放弃。
- **税与生命周期**：过境税先扣款再支付，同一航段同一城市不重复收取；缺钱等待。九旬无位置进展转为等待。回合更新直接修改登记对象，避免覆盖击破回调标志。已完成记录不会继续占用商人名额或拦截新部队的回调。
- **停靠约束**：停靠/等待部队通过共享移动步耗回调返回不可通行；范围、寻路、路径计费共用这个入口。使用原子读写的单位表并检查统领，防止其他统领复用槽位后被误冻结。贸易现在要求 `move=1` 且移动模块安装成功；三类实际游戏行为仍须实机确认。
- **行情快照**：记录观察时的价格指数、事件倍率、库存，不把新事件或当前库存拼进旧行情；过期行情视为未知。
- **命令生命周期**：排队任务使用共享所有权，超时不再留下栈上悬空任务；读档取消待执行命令并唤醒调用方。已经开始执行的命令在调用方超时后仍可能完成，因此不要依据超时结果直接重试交易。
- **AI 部分调整**：先选择商人，再使用其价格、税率和载量评估航线；跨起点按收益与时间估计比较。到站交易调用玩家同一买卖函数；真实路径成本和分段运输尚未完成。

## 数据与存档

`trade.bin` 生成格式为 **v4**，继续读取 v1～v3。v3 内容之后追加五个 uint32 库存参数和 `C × G` 个 uint16 需求倍率（千分比）。字段布局同时记录在 `tools/trade_data.py`。

`TRAD` 保存为 **v7**：外层仍为 `TRAD + uint32 version + uint32 payload_size`，负载为 `uint32 raw_size + Windows XPRESS_HUFF 压缩流`。v6 解压后是完整 v5 负载；v7 在其尾部追加 `uint32 count` 和 count 个 `{int32 payer, int32 receiver, int32 remainder}`。余数单位为万分之一金，仅保存 1～9999，交易方/收税方必须有效且不同，键不重复；旧档迁移为空，不追补旧税。解压上限 64 MiB，长度、压缩流和业务字段全部验证后提交；需要 Windows 8 或以上（系统 cabinet.dll），不依赖额外分发的压缩库。保留 v1～v6 读取支持。

v5 负载：保留旧记录前缀，追加库存、完整观察快照、稳定商队 ID、行程状态、货物批次、航段已缴税城市、待入账余额；v5 在 v4 负载尾部追加活动行程账本和结束行程账本。支持 v1～v3 迁移：旧货物转为批次，旧待扣税债保留，不可信的旧行情失效。旧存档无法恢复过去未记录的真实市场库存，因此以初始库存开始。

解析先验证临时数据再提交。无法理解或损坏的 TRAD 块（包括可识别的截断头和截断负载）原样保留，并停止贸易操作；`trade=0` 也原样传递贸易块。**原样保留不等于修复损坏存档**，也不保证关闭贸易期间移动过的部队能无缝恢复原行程。
