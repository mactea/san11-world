## 已确认的原生格式

`Media/san11pkres.bin` 使用 LINK 索引：16 字节头部，后接每项 8 字节的 offset/size。走舸模型是逻辑模型 327、资源 0x8AD；贴图逻辑编号 62、资源 0x8AC。楼船逻辑模型 328，斗舰逻辑模型 329。

WKMD0010 头部为 80 字节，+24 为最小/最大包围盒六个 float；+48 骨矩阵数、+52 骨矩阵数据偏移、+64 顶点颜色流数、+68 缓冲描述数、+72/+76 为两个绘制批次数。每个缓冲描述 80 字节，模型内使用偏移、GPU 上传后填入运行时 COM 指针。

本资产沿用走舸元数据，顶点 FVF=0x11A、步长 44：位置 3 float、混合权重 3 float、法线 3 float、UV 2 float。每点权重 (1,0,0)，绑定原模型静态船壳骨 5；索引为 uint16。单个不透明批次改为 D3DPT_TRIANGLELIST，关闭第二批次。贴图为 256×16 BGRA、15 色材质调色板。GLB/OBJ 的顶点和材质是原创生成。

已实际调用的原生入口（当前 EXE 版本）：

| 地址 | 用途 | 测试方式 |
| --- | --- | --- |
| 0x44A5D0 | 模型绑定，allocator=0 时引用输入缓冲 | 独立进程通过 |
| 0x44A660 | 创建并填充 VB、颜色 VB、IB | D3D9 HAL 通过 |
| 0x44A8B0 | 释放模型 GPU 缓冲并清空指针 | 独立进程通过 |
| 0x44A460 | 将模型定义存入实例 +0x58 | 已接入，保留原生模型/骨架 |
| 0x44AE20 | 原生模型绘制与轮廓通道 | 隔离游戏实际绘制通过 |

## 独立贸易船显示实现

实现位于 `worldmod/src/trade_ship_visual.cpp`。不替换资源 0x8AD 或全局走舸模型：只有 `merchantShip()` 身份检查通过的单位使用私有网格与贴图。普通船沿用原生绘制。

已找到调用链：

1. `0x568870` 更新单位视觉子对象；`0x5688E8` 调用 `0x411F50`，输入视觉描述是子对象 +0x30，输出渲染 actor。
2. actor 大小 0x50；+0x00 为变换矩阵、+0x40 动画时间、+0x44 类型、+0x45 变体、+0x48 链表指针、+0x4C 渲染实例。
3. `0x411CF0` 根据 actor 类型/变体选择原生模型；`0x411D79` 调用 `0x44A460` 绑定实例。
4. `0x412169` 通过实例虚表 +0x18 绘制；原实现 `0x44B700` 根据模型批次表进入渲染。

视觉子对象经父对象、单位对象的 +8 字段取得 unit ID。actor/实例复用时覆盖身份标记，绘制时再次检查贸易船身份。实际地图实例使用派生虚表 `0x769C20`，绘制槽位在 `0x769C34`；基类虚表 `0x794758` 不是该地图池的入口，这一差异已在实机修正。

私有资源沿用原生走舸骨架，绘制时传入私有模型，临时绑定调色板贴图，结束后恢复实际纹理，保持原生纹理缓存一致。原生走舸透明船桨通道不再绘制。文件缺失、格式不兼容、GPU 分配或绘制失败时回退走舸；失败不会逐帧反复读盘。设备 Reset/CreateDevice 前释放私有资源，下次绘制重新加载。

实机发现原生黑色轮廓将背面沿法线扩张约 0.1 单位，与双面帆和半径 0.018 的索具相交，造成黑点和表面覆盖。仅在新商船的一次同步绘制期间关闭该轮廓，随即恢复原生开关；普通船仍有轮廓。无需修改原始船只资源。船帆的灰白变化保留原生光照。

已有商船逻辑的 `merchantShip()` 使用单位地址范围、槽位和商人武将身份共同校验；新显示入口复用该判定。绘制回调没有阻塞获取贸易锁；原有主线程 `TryEnterCriticalSection` 防死锁修复保留。
