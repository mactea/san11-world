# AI 后方运输规则

本规则由 `tools/patchgen/ai_transport_policy.py` 定义，经 `m8_sites.py`
纳入补丁生成流程。游戏启动时读取 `worldmod_bases_caves.txt`，旧存档无需转换。

## 生效范围

- 后方运输调整限于运行时留兵系数 N 为 0 的城市。
- 临战状态仍由原版判断；运输许可、可用武将、行动力、粮食及路线条件保留。
- 前线 N 非 0 时，普通调拨继续按 N × 7,500 留兵，使用原版编组。
- 建设达标门槛仅在普通调拨调用处取消，共用的建设检查函数不变。

## 后方保留兵力与编组

- 普通调拨保留至少 3,000 兵。
- 邻接救援分支原本就对城市保留至少 3,000 兵，继续使用原计算。
- 城市向所属港口补充固定 3,000 兵时，后方来源城需有至少 6,000 兵。
- 普通后方调拨的最低运输数量降为 1,000，单队不超过原版运输上限 60,000。
- 无需凑齐战斗编组所需兵装。有库存时，可携带一种枪、戟、弩、马，数量不超过本队兵数；无兵装时仍可运兵。
- 无需预先凑齐每队 400 金；可以少带或不带金。
- 从本城当前可用武将名单选取将领；不调用战斗部队的兵装编组筛选。

每队人数受以下上限共同约束：

1. 来源城现兵减去 3,000。
2. 单队 60,000。
3. 来源城可用粮食扣除原版保留粮食后，除以 2。
4. 目标容量的 90% 减去目标现兵及本次循环已经安排的运输兵数。

结果不足 1,000 时不派队，因此可能留下 3,000～3,999 兵。
粮食扣除和来源城留兵仍由原版后续检查复核。

## 向前线接力

- 继续使用原版局部可达据点搜索，同军团、临战状态和路线科技筛选保留。
- 军团设置了有效且属于本军团的输送城市时，后方候选城市必须更接近该城市。
- 距离相等或更远的候选不接受，已到指定输送城时不继续按此规则向外接力。
- 距离矩阵继续根据“难所行军”科技选择。
- 未设置、输送目标已易主或目标无效时，回退原版向前线方向的筛选。
- 后方接力城市不必带有原版补给需求标志，但至少应有 1,000 兵的接收空间。

接力严格缩短到指定城市的距离；不会主动跨军团，也没有新增穿越敌城的路线。

## 验证和边界

`python -m unittest discover -s tools/patchgen -p 'test_ai_*.py'`

新增测试读取安装目录的原版 EXE，在 Unicorn 中执行原版调拨指令及生成、交付补丁，
检查留兵、粮食、金钱、可选兵装、容量、行动力、许可、接力方向及栈恢复。
未安装原版 EXE 时，依赖它的新测试会跳过。

这里的后方最低留兵是运输底线，不是强制每城每旬都只剩 3,000 兵。
缺粮、缺将、行动力不足、没有合适接力目标或目标接近满员时，仍会积兵。
容量检查继承原版运行时预算；本次循环的已派兵数会计入，未重写全势力在途运输预约机制。
这些测试不等于真实游戏中完整过回合验证。
