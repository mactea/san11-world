# 商队补给与避险（2026-11-11）

针对商队在原生游戏中溃败的问题，本次实现往返备粮、续航补给检查和危险区绕行。不改变护卫人数、船型属性、市场价格及存档结构；原生耗粮与战斗仍运行。

## 往返备粮

`trade_safety.h::provisionFood` 使用保守规划标准：每旬按 `ceil(护卫人数/10)` 预留，行程增加25%余量，另加4旬停靠与交易余量。组队至少保留原配置 `trade_food`（默认3000粮）；运输队原生粮食容量100000，超过时拒绝该商路，禁止截断后出发。例如500护卫、预计往返100旬，准备6450粮。这是备粮预算，不是修改原生粮耗公式，也不是保证未来天气和任意长时间等待都不缺粮。

地理报价先按双程及两端接驳预估。真实队伍登记后、首次执行移动前，调用 `movementRouteTime` 检查实际路径和反向路径当前季节耗时；无法取得时用每5步一旬的保守代理。实际绕行需要更多粮时，先从出发城市追加装载；库存不足则撤销新建并返还已实际预留的资金、兵力、兵粮及市场库存。接驳粮食另计，不远程转移出资城粮食。

`trade_panel` 中单品及组合报价显示往返备粮。自动贸易将动态携带粮按本城原生粮价折算进粗估净收益；不是再收一次现金。地理报价仍不能精确预知真实绕行、季风变化及未来战争，因此出发前再复核。委任城市维持9000粮的原有军事储备要求，包括追加装粮。

## 续航与回程

`depart` 在收续航费和设置移动命令前，对下一段实际路线核验剩余粮食。驶回原出资城检查单程，去其他市场按往返预留；返程不强迫重新凑足组队的3000粮下限。充足则不扣粮；不足且停靠本方城市，只调出实际差额，重试不重复扣粮。外地市场不能直接调走他国军粮；不足时阻止续航，显示需要在本方市场补给。

自动回程在买入返程货物之前检查补给及安全路线，避免补给已经不足时继续花预算买货。已经买过返程货的重试由 `depart` 再检查，不重复买货。城市库存不足、超过容量或接口调粮失败均返回明确原因；部分调粮失败和装载不足退回未装部分。已有在途商队不会凭空获救或补满，长期停靠仍可能继续耗粮，不能将“暂停”视作免耗粮状态。

## 避敌寻路

`trade_safety_runtime.inc` 复用原生敌对判断 `0x4b5cc0`，排除己方及非敌对对象。每次贸易路径查询重新采集敌军和敌方城市、关隘、港口位置：战斗部队周围4格、据点周围3格形成禁行区。运输队不作为攻击源，内政设施不作为据点禁区。现阶段读取当前原生对象位置，没有模拟未来敌军移动或依据战争迷雾限制侦察。

禁行检查接入已有移动步回调，与海运禁上岸规则同时生效，覆盖原生A*、移动范围和执行。仅已登记且统领匹配的贸易队伍使用商队危险图；普通军队保留原规则。查询期间可绕行；无安全泊位／通道则停等，不退回穿越危险区的最短路。外交与敌军位置变化在下一次规划时刷新。

危险图采用不可变位图快照，逐单位原子发布；移动回调不遍历对象、不获取贸易锁。1000×1800地图每支快照约225000字节；航次结束和读档清理旧缓存，防止单位复用和长期游戏累积。敌军可能在商队移动后靠近；已经被包围的商队也可能没有安全出口，本实现不提供无敌、瞬移或自动救援。
