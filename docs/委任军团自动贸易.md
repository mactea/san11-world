# 委任军团自动贸易

2026-11-07：玩家委任军团现在会为尚未配置贸易计划的城市建立自动贸易计划。读入旧存档后，在下一次旬结算开始评估，无需逐城手动开启。

## 规则

- 每城每月预算默认 4,000 金，同城最多同时存在两支未结束的自动商队。预算包含购货和费用预留，销售收入不会增加当月预算。
- 目的地和商品由现有自动贸易规划器选择，支持组合货物。只考虑已知、开放、符合运输条件的市场，预估往返净收益至少达到成本的 10%；出发仍须真实路径校验。预估收益不保证实际售价或途中安全。
- 每次派队前，城市至少有 6,000 金，且扣除本队护卫和兵粮后至少保留 5,000 兵、9,000 粮。资金支付继续遵守城市至少保留 2,000 金的约束。
- 生成的计划默认使用普通商队。海运商船仍需在自动贸易菜单中选择，并满足港市与水路条件。
- 到达后销售货物，再评估回程货物；没有预算内的盈利回程组合时空载返回。暂时的市场、预算或路线异常自动安排下月重试；失去城市归属时停止并等待处理，不替新城主花钱。
- 收回直辖后停止该委任计划的新派遣。已出发商队继续完成销售与返程，返程阶段不再新增购货。已购入的返程货物仍带回。已有承诺产生的税费、通行费和返程费用继续按原预算结算。
- 玩家已经保存的计划优先，包括暂停计划。系统不会覆盖其预算、商品、目标或开关。在自动贸易菜单保存委任计划后，该计划转为玩家设置，此后由玩家控制，不再随军团委任开关变化。
- 临时商人仍使用现有隐藏、回收和归属保护，不占用历史武将派遣；现有驻军策略、组合特技和贸易船外观保持不变。

## 界面与诊断

城市的“贸易 → 自动贸易”中显示“计划来源”：军团委任或玩家设置；未指定优先城市显示“系统择优”。未派遣原因可在“执行状态”查看。`trade dump` 也会记录来源、开关、预算、已占用金额和执行状态。

## 实现与存档

原生直辖判断函数 `0x47a6d0` 最终比较军团记录 `+8 == 1`。实现验证城市所属玩家势力、军团有效性和军团归属后，将势力内序号 2～8 判为委任；不使用全局军团槽号判断直辖。

复用 `trade_auto_runtime.inc` 的派遣与往返流程。每旬先同步委任状态，再处理在途商队和计划，避免刚收回直辖仍发起新购货。月预算、已派遣月份和费用账户均复用原有机制。

TRAD 扩展升级至 v12，在 v11 尾部追加每个计划的委任来源标记，并允许目的地 -1 表示系统择优。v1～v11 仍可读取，旧计划一律按玩家设置保留。v12 的来源和预算一并存档；不会通过读档、重复刷新或重新委任重置当月支出。旧版 DLL 不识别 v12，因此部署时保留旧 DLL 和部署前存档备份。
