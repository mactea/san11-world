## 配置和运行

在 `worldmod.ini` 的可执行文件对应节中设置，例如：

```ini
[san11pk_render]
render_backend=9on12
terrain_renderer=original
render_present_interval=3
terrain_anisotropy=0
```

| 配置 | 行为 |
| --- | --- |
| `render_backend=system`, `terrain_renderer=original` | 系统 D3D9；代码默认值，也是回退基线 |
| `render_backend=9on12`, `terrain_renderer=original` | Windows D3D9On12 转译，保留原始绘制；当前以缩减栈预留后的测试 EXE 继续验证 |
| `render_backend=9on12`, `terrain_renderer=dx12` | 部分地形由原生 DX12 提交，其余仍经 D3D9On12 |

改配置后重启游戏。`dx12` 必须配合 `9on12`；未知配置使用原始路径。On12 工厂不可用或设备创建失败时尝试系统 D3D9，并记录实际后端。设备创建失败后的回退分支尚未做故障注入验证。无需在代理 DLL 旁再放 DXVK 的 `d3d9.dll`。

`render_present_interval` 只覆盖窗口化 9on12 的呈现参数，代码默认值仍为 `0`；上例的 `3` 是当前测试副本使用的实验配置。改后重启，回退到 `0` 即恢复游戏原始呈现设置。

| 值 | 行为 |
| --- | --- |
| `0` | 不改游戏的呈现间隔 |
| `1` | 显式 ONE；诊断用途，本机没有稳定收益 |
| `2` | IMMEDIATE，不额外限帧；只用于短时诊断 |
| `3` | IMMEDIATE，加高精度等待计时器限制为每秒 60 次提交 |

模式 3 在最外层 Present 前等待，等待时间计入提交间隔，不计入 Present 调用内耗时；载入或长帧后重新同步，不追赶积压帧。计时器创建失败时保留游戏原参数。该限帧不是垂直同步，不能保证显示器实际显示 60 FPS 或消除撕裂；尚需显示帧时间验证。全屏、系统 D3D9 和设备创建回退不应用此覆盖。依据：[Microsoft D3DPRESENT](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dpresent)。

`terrain_anisotropy` 是独立的画质实验开关：`0`（默认）不覆盖；`2/4/8/16` 请求对应倍数，按设备能力限制。其他值及不支持的设备禁用覆盖。只与 `terrain_renderer=original` 配合，在 system 或 9on12 路径上生效；混合原生地形模式会禁用它并写日志。需要重启才能读取配置。

覆盖限定在已识别的地形调用区间、基础地形顶点着色器、无像素着色器、单纹理阶段、带 mip 链且启用 mip 采样的二维纹理。保留点采样和已有的更强各向异性过滤；只临时修改采样器 0 的 MINFILTER/MAXANISOTROPY，并在该次绘制返回时恢复。Reset 前停止覆盖，成功后重新读取能力；设置或恢复失败会记录错误并停止后续覆盖，直到设备重建。未新建地形纹理或增加高清素材。依据：[Microsoft 各向异性过滤](https://learn.microsoft.com/en-us/windows/win32/direct3d9/anisotropic-texture-filtering)、[采样器状态](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dsamplerstatetype)。

`render_status` 的 `Terrain filtering` 行报告请求/有效倍数、覆盖/跳过次数、状态错误及最近的 `last_error` HRESULT；`render_timing_reset` 同时清零这些诊断值，但不会重新启用因失败而停用的过滤。启用过滤的基线报告必须包含实际覆盖次数且无状态错误，否则采样脚本拒绝报告。能力支持和状态测试不能证明地形图集无串色、移动无闪烁或画质提高，当前仍默认关闭。

本次独立测试副本是 `worldmod/build/render-game/san11pk_render.exe`，存档在副本的 `UserData_render` 下，当前配置为 `9on12/dx12`、`automation=0`。该测试启动器按目录隔离单实例互斥锁，可与原游戏共存，同一测试目录仍只允许一个实例。原安装目录未部署本次 DLL。

为使测试副本使用 NVIDIA，而不是笔记本默认的 Intel 核显，仅为此测试 EXE 写入了 Windows 当前用户图形首选项 `GpuPreference=2;`，原值备份在 `build/gpu-preference-backup.json`。可在 Windows 图形设置中移除此 EXE 的首选项；本次原值为空，未改变全局显卡设置。辅助互操作测试程序的临时图形首选项在测试后移除。

## 实现范围

- `src/render_backend.cpp` 动态调用系统 `Direct3DCreate9On12`，报告实际适配器、后端、资源互操作结果和帧间隔。正常 system 模式不立即加载 D3D12/着色器编译器 DLL。
- 请求原生地形时，提前创建 D3D12 设备与一条 Direct queue，并通过 `D3D9ON12_ARGS` 交给 9on12；原生绘制复用该队列。实际设备身份不匹配或发生工厂/设备回退时停用原生绘制，保留原始地形。`native_shared_queue=1` 表示已匹配；Reset 保留队列，重建地形资源。原始地形配置不走这套工厂覆盖。
- `src/terrain_dx12.cpp` 在原有地形绘制位置提交 DX12 命令。通过 `IDirect3DDevice9On12` 借用颜色和深度资源，在原始绘制前归还，并使用 fence 协调。没有在 EndScene 上额外覆盖一层地形。
- 新构建的 DX12 候选接管基础材质、叠加纹理、轮廓和光照。不支持的状态/格式走原始绘制。早期版本的岸线差异尚需用新构建在游戏内复核；后台像素对照不替代此验收。
- 原游戏仍负责可见性和地形几何生成。地形 WRITEONLY 缓冲区 Lock 返回普通 RAM，Unlock 再向原始映射写入，避免读取写合并显存映射导致严重降速。
- 独立纹理副本保留 mip 链；纹理分配预算为 96 MiB，上传缓冲区为 4 × 8 MiB。该数值不包含原 D3D9 资源、CPU 影子数据、描述符、PSO 或临时上传资源，不是进程总显存上限。无 LRU 淘汰，预算不足时保留原始绘制。Reset 释放资源并重建。
- 当前只验证该游戏的 x86 `IDirect3DDevice9::CreateDevice/Reset` 路径。不能视为通用 D3D9Ex 或任意游戏的 DX12 包装器。地形识别依赖本项目支持的 EXE 地址布局。
