### 快照与生命周期

`object_capture.cpp` 使用互斥注册表和不可变共享快照：写 Lock 返回 CPU 暂存区，Unlock 前向原映射复制，驱动成功 Unlock 后才发布。读取者持有旧版本时，后续部分改写/释放不影响旧数据。版本号不会随 Reset 清零；DISCARD 后仅已初始化区间可绘制。所有 COM 调用位于快照互斥锁之外。

managed 缓冲的已发布快照可跨 Reset 保留；正在 Lock 的重定向指针保留到 Unlock，但旧代数据不再发布。失败 Unlock、预算不足和缺少有效快照均退回旧路径，不使用过期版本。这个机制不等于跨多个缓冲区的整模型原子事务，也不改变原游戏资源发布责任。

## 已验证的水面输入契约

静态文件证据由 `tests/audit_render_paths.py` 生成到 `build/offline-migration/`，包含代码块汇编、原始着色器和 JSON。六个关键代码块有 SHA256 版本校验；审计只读取 EXE，不执行它。运行时坐标补丁必须另行验证。

| 项目 | 已确认的值 |
| --- | --- |
| 世界主绘制入口 | `0x5A1D50`；地形 `0x421B10`，物体 `0x41E040`，后段水面 `0x41DB10` |
| 水面状态设置 / 绘制 | `0x4227E0` / `0x422C20`；包装调用 `0x422D24` |
| 顶点 | 单流 stride=24：float3 POSITION、DWORD COLOR、float2 TEXCOORD |
| 拓扑 | TRIANGLESTRIP，16-bit 索引；每格 `v,v,v+1,v+2,v+3,v+3`，含退化连接 |
| 着色器 | 字符串 VA `0x74E7C0`；shader/declaration 指针 `0x8F78E8/0x8F78EC` |
| 管理器 | `0x4E482FC`，VB `+0x5558`、IB `+0x555C`、两纹理 `+0x5560/+0x5564`、phase `+0x5570` |
| 动画 | 8×8 图集，64 相位；两组按既定顺序绘制 |
| 岸线颜色 | 掩码位有值取 `0x00FFFFFF`，否则 `0x20FFFFFF` |
| 固定状态 | 无剔除、ZWRITE=0、SRCALPHA/INVSRCALPHA、ADD、alpha > 0、纹理与当前颜色相乘、线性 MIN/MAG、U/V wrap |

原始着色器哈希：`e5d0438981d382f7f9eef8254ba2d25712d9122bcace9d5b01fbfb6ba9177cb1`。它使用 c6/c10 变换、c26 雾、c27 距离 alpha，颜色和 UV 来自顶点。测试中将输入转换为基础地形双流并令 c24 为零，保留原始水面着色计算。参考路径执行真实 VS1.1 和 triangle strip；原生路径执行转换后的 triangle list。

`tests/water_reference_test.cpp` 每个相位都包含 16 掩码、两层叠加，覆盖普通、透视加雾、雾加深度遮挡，重复三次设备 Reset。使用确定性合成图集，**未解码或验证实际 water.wft 素材**。这个测试证明所列条件下的转换等价，不证明实际游戏资源/世界偏移/继承状态已兼容。

生产接入前仍须落实：

1. 将水面单流与 strip 作为独立输入契约处理，保留两组顺序、索引退化连接和深度只读语义；不能直接扩大现有地形调用范围。
2. 对管理器 VB/IB 的创建、Lock/Unlock、释放、Reset 建立 shadow 跟踪，避免 WRITEONLY 缓冲回读和释放后复用。
3. 校验真正的 shader/declaration、材质 stage、纹理身份及继承的雾/mip/深度状态；不支持时在原始绘制前 flush。
4. 对世界坐标补丁和纹理资源做独立参考，覆盖 buffer 改写、动画周期边界、两组长度及 Reset。
5. 才能加入生产水面调用点，并安排真实岸线、换季、读档和长时验收。

现有 native hook 只接受调用范围 `[0x41DF50, 0x421B10)`；水面调用在范围外，当前游戏仍使用原水面路径。

## 物体、动画与 UI 的接入依据

世界物体已有路径：`0x41E040 → 0x423820`，排序 `0x423660`，开始/结束 `0x41B420/0x41B1C0`；对象虚调用后可经 `0x41CF70 → 0x4231B0 → 0x41B960 → 0x41B7B0 → 0x41B3B0 → 0x41B2F0`，已确认包装绘制点 `0x41B38C`。城墙相关路径 `0x41C630`、高度查询 `0x4178A0`。这些证据不足以将全部世界物体等同为建筑。

静态物体的下一份必要输入是：顶点 declaration/stride、index 格式与 base 范围、各材质的纹理 stage 与 alpha/depth/cull、局部到世界矩阵、绘制顺序和资源生命周期。先以一个已识别的物体材质建立离线原始/原生图像对照，再扩展路径。

`0x793928/0x793BD8/0x794150/0x7943E0` 的着色器含混合权重声明，属于蒙皮候选；还没有模型类别、骨骼常量布局和动态更新节奏的可靠映射。植被 alpha test、透明特效混合顺序、单位蒙皮必须分别建立参考，不能把这些候选直接标为已识别单位路径。

UI 调用点仍有未分类项。间接调用的 COM vtable 偏移 `0x144/0x148/0x14C/0x150` 仅是线索，不能仅凭偏移断定是 D3D9 绘制。下一步应定位预变换顶点/FVF、字体图集、裁剪、半像素坐标和 UP 临时数据复制语义。现有 DP/DIP/DPUP/DIPUP 回退会先 flush 原生批次，应继续保留这条顺序边界。
